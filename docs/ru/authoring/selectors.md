# Селекторы

Scenaria использует локаторы **Playwright**. В шагах селектор — строка в кавычках: `нажимаю "#login"`, `вижу "text=Сохранить"`.

Проверка **доступности** кнопки (не только видимости): `проверяю что доступно "#submit"` / `проверяю что недоступно "#submit"`. Playwright учитывает `disabled`, `aria-disabled` и перекрытие другими элементами.

## Приоритет при записи

При live-записи (`internal/selector/strategies.go`):

| Стратегия | Пример | Когда |
|-----------|--------|-------|
| **testid** | `[data-testid="submit"]` | Стабильный атрибут в приложении |
| **id** | `#login-form` | Уникальный `id` |
| **aria / role** | `role=button[name="Войти"]` | Кнопки и ссылки |
| **label** | `label=Email` | Поля с `<label>` |
| **placeholder** | `[placeholder="Поиск…"]` | Без label |
| **text** | `button:has-text("Каталог")` | Видимый текст |

Клики: короткий text-селектор; цепочка `>>` при дубликатах.  
Поля: label → placeholder → aria → name → testid → id.

## Цепочки (`>>`)

```gherkin
Когда нажимаю "nav >> text=Товары"
Тогда вижу "main >> h1"
```

Разрешение через `ResolveChainedLocator`: контейнер, затем цель.

## Рекомендации

1. **`data-testid`** на кнопках и формах.
2. **`role` + `name`** вместо длинного CSS.
3. Укорачивайте селекторы после записи.
4. UI Scenaria помечен `data-scenaria-ui` и не попадает в сценарий.
5. Меню по hover: `навожу` или `>>` на пункт.

## Переменные `{{имя}}`

```gherkin
Когда нажимаю "{{button_id}}"
И заполняю "{{email}}" в "input[type=email]"
```

До 16 проходов подстановки; циклы — ошибка. Сложные значения — `запоминаю … как "имя"`.

## Проверка

| Способ | Как |
|--------|-----|
| IDE | **Селекторы на странице** или **Проверка в браузере** |
| CLI | `scenaria validate ./examples --browser` |

Шаги URL ждут совпадения ~5 с после SPA-навигации.
